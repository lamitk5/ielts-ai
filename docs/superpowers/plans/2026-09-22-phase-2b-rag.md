# Phase 2B RAG + Admin CMS Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (\`- [ ]\`) syntax for tracking.

**Goal:** Build Phase 2B as a governed, provider-independent RAG and Admin CMS foundation while preserving the existing Tutor API contract. This plan is for a later implementation run; the current request changes documentation only.

**Architecture:** PostgreSQL with pgvector is the knowledge store. A shared DocumentIngestionService is called by both the temporary-token Admin API and the CLI manifest runner. Only approved, active, current, successfully indexed versions are retrieved by vector similarity. Retrieved evidence is bounded, passed through the existing provider abstraction, and returned through normalized citations and grounding states.

**Tech Stack:** Spring Boot, Spring JDBC, Flyway, PostgreSQL, pgvector, Apache Tika, Gemini provider adapters, React, React Router, Vite, Vitest, Testing Library, and the existing Academic Luxury design system.

**Spec:** docs/superpowers/specs/2026-09-22-phase-2b-rag-design.md

## Global Constraints

- Implement only Phase 2B; do not implement phases beyond this scope.
- Preserve POST /api/ai/chat and its normalized response fields.
- Do not expose Gemini request or response payloads to the frontend.
- Do not hardcode an API key, embedding model, vendor vector payload, or fake citation.
- Use PostgreSQL plus pgvector for production retrieval.
- Keep approval, indexing, activation, and deactivation as separate transitions.
- A version that is not approved, active, current, and indexed after its latest approval must never be retrieved.
- Never auto-approve an upload from Admin UI or CLI.
- Keep the temporary admin token at the HTTP boundary.
- Do not add JWT, OCR, STT, full exam modules, or a production identity system in this phase.
- Keep score language clearly estimated where applicable.
- Preserve keyboard access, visible focus, mobile safety, and reduced motion.
- Every task starts with a failing test or contract check, implements the smallest change, then runs the green command.
- Do not leave unresolved placeholder prose in implementation documents.

## Review Focus

Review lifecycle correctness for stale approvals, reapproval, deactivation, and version replacement; deterministic extraction and chunking; embedding dimension validation; duplicate checksums; retrieval filters; prompt-injection resistance; source-bound citations; shared Admin and CLI ingestion; temporary-token isolation; frontend backward compatibility; accessibility; responsiveness; reduced motion; and scope control.
