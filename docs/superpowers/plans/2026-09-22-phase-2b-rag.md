# Phase 2B RAG Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement the approved Phase 2B RAG architecture as a governed PostgreSQL/pgvector knowledge pipeline, provider-independent grounded Tutor responses, and a temporary-token Admin CMS.

**Architecture:** Preserve the existing React Tutor to Spring Boot to AiProvider to GeminiAiProvider path for generic chat. Add conservative RAG orchestration beside it: query embedding, governed pgvector retrieval, bounded context construction, existing Gemini generation, and source-bound grounding validation. Admin upload and manifest CLI both call one DocumentIngestionService.

**Tech Stack:** Spring Boot 4.1.1, Java 21, Spring Web MVC, Spring WebFlux WebClient, Spring JDBC, Flyway, PostgreSQL 16 with pgvector, Apache Tika 3.2.2, Testcontainers, React, React Router, Vite, Vitest, Testing Library, and the existing Academic Luxury UI system.

**Spec:** docs/superpowers/specs/2026-09-22-phase-2b-rag-design.md

## Global Constraints

- Use PostgreSQL plus pgvector for production retrieval, with Flyway migrations and CREATE EXTENSION IF NOT EXISTS vector.
- Use vector(768); RAG_EMBEDDING_DIMENSION must validate to 768 until a deliberate migration changes the schema.
- Keep Gemini generation configurable through GEMINI_MODEL with the existing gemini-3.8-flash default and LOW thinking behavior.
- Keep embeddings behind EmbeddingProvider and keep GEMINI_EMBEDDING_MODEL as a required backend configuration value; do not invent its identifier or place it in React.
- Support PDF, DOCX, and TXT only; do not add OCR.
- Route Admin upload and backend/rag-data manifest ingestion through the same DocumentIngestionService.
- Retrieve only current versions with rightsStatus APPROVED, active true, indexStatus INDEXED, and indexedAt on or after approvedAt.
- New uploads always start PENDING_REVIEW and inactive; extraction success never approves or activates a source.
- Store originals outside Git under backend/data/rag/uploads with generated safe names and ignore that directory.
- Protect only /api/admin/rag/** with X-Admin-Token backed by RAG_ADMIN_TOKEN; keep the token out of domain services, logs, URLs, localStorage, and source control.
- Preserve POST /api/ai/chat, generic Phase 2A chat, normalized application fields, and provider-independent React code.
- Return real citations only from retrieved chunks; never fabricate source chips or expose raw Gemini payloads, embeddings, secrets, or chain-of-thought.
- Treat retrieved text as untrusted evidence and defend against prompt injection.
- Use TDD for each task: write a failing test, run the exact red command, implement the smallest change, rerun targeted tests, then commit.
- Do not implement Reading, Listening, Writing, or Speaking engines, JWT, OAuth, OCR, STT, cloud storage, production deployment, or unauthorized Cambridge IELTS data.
- Do not call real Gemini in unit tests; use local HTTP stubs or deterministic fakes.
- Keep commits small and logical; never commit real credentials or source documents.

## Review Focus

- A reapproved document with old indexed vectors must remain excluded until its current version is reindexed after the new approval timestamp; Task 6 and Task 7 pin this with lifecycle and SQL tests.
- A source can be technically indexed but still unavailable when rights change or active becomes false; Task 7 owns integration tests for every governance predicate.
- Embedding model or dimension drift must fail before vector persistence and must never mark a version INDEXED; Task 5 and Task 6 own these tests.
- Retrieved text containing an instruction must remain delimited data and cannot create a citation outside the retrieved set; Task 8 and Task 9 own the prompt-injection and provenance tests.
- An unavailable RAG dependency must not break generic hello chat or create fake citations; Task 9 owns direct-path and failure-fallback tests.
- Temporary admin credentials must never appear in logs, URLs, browser localStorage, or business-service signatures; Task 10 and Task 13 own boundary tests.
