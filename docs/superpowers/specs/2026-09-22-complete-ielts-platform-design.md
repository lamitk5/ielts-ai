## Architecture decisions

1. Authentication uses PostgreSQL users plus opaque random session tokens stored hashed in `auth_sessions`; tokens are returned only once at login and sent as `Authorization: Bearer` from the frontend. This avoids adding a JWT library and supports immediate logout invalidation.
2. `CUSTOMER` is the default member role and `ADMIN` protects `/api/admin/**`. The existing `X-Admin-Token` adapter remains available only as a local compatibility path until the authenticated admin UI is migrated; it is not used by member APIs.
3. Practice fixtures are project-owned synthetic data in Java resources and are immutable application data. Official answer keys are deterministic and never generated by Gemini.
4. Writing and Speaking use provider-independent DTOs. Gemini quota/unavailability produces a controlled unavailable result; the frontend never fabricates an assessment.
5. Speaking implements browser-independent prompt/input/attempt persistence and an explicit `STT_NOT_CONFIGURED` boundary. It does not claim a transcript or successful recording when permissions/provider support are absent.
6. Existing `?demo=member` remains an explicit demo mode. Authenticated `/` uses real profile/progress data; guest `/` never receives personal values.
